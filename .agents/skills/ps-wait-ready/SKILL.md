# Skill: Wait-Ready — readiness-gate опросом

## Идея

Вместо `Sleep N` «чтобы успело» — опрос готовности до таймаута. Быстрее (не ждёшь
лишнего) и надёжнее (дождёшься, если медленно). Готовность отдаётся **кодом
возврата** (0 = готов), скрипт poll'ит с интервалом.

## Контракт readiness-эндпоинта (`status --ready`)

Требования (сторона программы):

1. **Быстрый** (~100 мс, без тяжёлых sleep внутри) — его дёргают каждые 500 мс.
2. **Проверяй РОСТ, не существование.** «Артефакт есть» ≠ «процесс жив»: убитый
   продьюсер оставляет stale-артефакт (замороженный счётчик). Без growth-check —
   ложный `ready=1` на трупе. Правило: дважды прочитать монотонный счётчик через
   окно (~3 периода продьюсера) и требовать строгого роста.
3. **Выход — код + одна строка.** `ready=1 seq=N` / exit 0, иначе `ready=0` / exit 1.
   Скрипт гейтится кодом, строку показывает в INFO для диагностики.
4. **Без побочных эффектов.** Только открыть/прочитать/закрыть, состояние не менять.
   Настройки можно не читать.

Псевдокод эндпоинта:

```
func status_ready() -> exit_code:
    h = open_shared_state()          # секция / файл / мьютекс продьюсера
    if h is null:
        print("ready=0")             # продьюсера нет вообще
        return 1
    seq1 = read_monotonic_counter(h) # seq кадров, tick heartbeat, ...
    if seq1 <= 0:
        close(h)
        print("ready=0")             # артефакт есть, но кадров ещё не было
        return 1
    sleep(3 * producer_period)       # окно: ~100 мс при 30 FPS
    seq2 = read_monotonic_counter(h) # повторное чтение ТОГО ЖЕ хэндла
    close(h)
    if seq2 <= seq1:
        print("ready=0")             # заморожен = stale, продьюсер мёртв
        return 1
    print("ready=1 seq={seq2}")
    return 0
```

## Паттерн polling-цикла (сторона скрипта)

Псевдокод:

```
deadline = now() + TIMEOUT          # напр. 10 с (холодный старт + запас)
t0 = now()
loop:
    out, code = run("app status --ready")   # код возврата — сигнал, out — для лога
    if code == 0:
        log("INFO: ready in {now()-t0}s ({out})")
        break                        # готов — дальше основная проверка
    if now() >= deadline:
        fail("not ready in {TIMEOUT}s (last: {out})")
    sleep(POLL_INTERVAL)             # напр. 500 мс >> длительности одной проверки
```

Тот же паттерн на PowerShell:

```powershell
$deadline = (Get-Date).AddSeconds(10)
$t0 = Get-Date
for (;;) {
    $out = ((& $Exe status --ready 2>&1) | Out-String).Trim()
    if ($LASTEXITCODE -eq 0) {
        $dt = [int]((Get-Date) - $t0).TotalSeconds
        Write-Host "INFO: ready in ${dt}s ($out)"
        break
    }
    if ((Get-Date) -ge $deadline) { throw "not ready in 10 s (last: $out)" }
    Start-Sleep -Milliseconds 500
}
```

Заметки: `$LASTEXITCODE` переживает `| Out-String`; интервал опроса должен быть
заведомо больше длительности одной проверки (500 мс при проверке ~100 мс);
таймаут покрывает холодный старт (инит + первый кадр), обычно срабатывает за ~1 с.

## Что НЕ гейтится (оставляй sleep/таймаут)
- **Смена состояния**, а не старт: hot-switch, переоткрытия, смена качества —
  продьюсер уже ready (счётчик растёт и до, и после), gate вернётся мгновенно
  и ничего не дождётся. Тут нужна пауза на применение + проверка НОВОГО состояния.
- **Тайминги фолбэков**: «нет сигнала через N секунд», замороженный кадр в окне —
  это предмет теста, а не ожидание готовности.
- **Debounce** (запись конфига → применение): gate видит «процесс пишет»,
  но не «конфиг применён».

## Мини-чеклист проверок (прогони после внедрения)

Эндпоинт (`status --ready` вручную, без скрипта):
- [ ] Нет продьюсера → `ready=0`, exit 1 (мгновенно, без висяков).
- [ ] Stale-артефакт (убить продьюсер, счётчик заморожен) → `ready=0`, exit 1.
- [ ] Живой продьюсер → `ready=1 seq=N`, exit 0; время ответа ~100 мс.
- [ ] Повторные вызовы подряд не меняют состояние системы (только чтение).
- [ ] Вывод — одна строка, формат стабилен (`ready=1 seq=N` / `ready=0`).

Polling-цикл (в скрипте):
- [ ] Холодный старт → `ready in ~1s`, дальше основная проверка зелёная.
- [ ] Медленный старт (искусственная задержка продьюсера) → ждёт, не падает раньше таймаута.
- [ ] Продьюсер не встал вовсе → таймаут 10 с + в ошибке последний вывод эндпоинта.
- [ ] Суммарная экономия/поведение зафиксировано (было фикс. N секунд × M фаз).
