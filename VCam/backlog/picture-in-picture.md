# Картинка в картинке (PiP): вторичный источник поверх основного кадра

## Идея

Добавить в кадр виртуальной камеры вторичный источник (например, физическую
камеру или второе изображение/видео) в виде небольшого окна в углу — как
классический PiP у стримеров.

## Мотивация

Сейчас виртуальная камера транслирует ровно один источник (static / video /
camera). Пользователям, которые показывают контент (демонстрация экрана,
документ, слайды), часто нужен второй источник — обычно веб-камера —
поверх основного кадра. Без PiP приходится запускать сторонние
микшеры/оверлеи.

## Возможная реализация

- Новая секция в `settings.json` (например, `pip: {enabled, source: {type,
  path/device}, corner, sizePct, margin, border}`), миграция/сиды — по
  образцу существующих секций.
- Рендер PiP — на стороне продьюсера кадров: второй `IFrameSource`
  (или прямое чтение камеры через `IMFSourceReader`) композитится в
  угловой прямоугольник основного кадра перед записью в shared-memory
  (`FrameWriter` — единственный писатель, 30 FPS pacing сохраняется).
- Масштабирование вписанного кадра с сохранением пропорций (аналог
  HighQualityBicubic из предпросмотра), рамка/тень для читаемости.
- UI: группа «Картинка в картинке» в `VCamSettingsUi` (вкл/выкл, выбор
  источника, угол, размер в %), превью PiP в `VCamPreview` — по образцу
  crop-рамки (`preview-crop-frame.md`).
- Хоткей показа/скрытия PiP на лету (секция `pipHotkey`), как у
  `sourceStaticHotkey` и т.п.
- Производительность: второй источник читается только когда PiP включён;
  бюджет кадра 30 FPS не должен заметно проседать (композитинг одного
  вписанного прямоугольника — единицы мс).
