# Скорость проигрывания видео (playback speed)

## Идея

Параметр скорости воспроизведения видеоролика (0.25×–4×, default 1×),
например `video.speed` в `settings.json` + слайбер/число в видео-панели
настроек.

## Мотивация

Замедленный ролик — как «медленная демонстрация» (0.5×), ускоренный —
когда длинный ролик хочется сократить. Удобнее, чем конвертация файла
внешним редактором.

## Возможная реализация

- Скорость — чисто pacing-множитель в `VideoFileSource::DecodeLoop`:
  `target = baseMs + (ts * speed) / 10000` (сейчас ts без множителя).
  MF Source Reader не имеет rate control (это Media Session),
  поэтому реализация на стороне нашего «плеера» — дешёвая.
- speed > 1: кадры выдаются чаще (декод 30 fps — потолок: 4× = 120 fps,
  при нехватке — дёрганность, клампнуть верх разумным 2×–4× по
  эмпирике). speed < 1: кадры держатся дольше (дублирование,
  frame-holding уже есть — без интерполяции).
- Контракт: `SourceConfig.speed` (+operator==), `Settings.VideoSection.speed`
  parse/serialize на C++ и C#, UI — поле в видео-панели (рядом с «Повтор»).
- Не зависит от паузы/хоткея/лупа; resume после паузы корректен
  (анти-дрейф `baseMs` пересинхронизирует).
- Юнит-тесты: парсинг/clamp (VCamTests, Settings — без MF).
- e2e: default speed=1 не ломает фазы; опционально фаза с speed=2.

## Питфолы

- При speed<1 «залипание» картинки — ожидаемое поведение (нет
  интерполяции кадров), описать в справке.
- Catch-up (`now > target+250`) при больших speed может периодически
  ресинхронизировать — нормально, но проверить на 4×.
