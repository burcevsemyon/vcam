# Авто-подбор источника по файлу

## Идея

Юзер больше не выбирает «статика или видео» — он выбирает медиа-файл, а тип
источника определяется автоматически (по расширению/содержимому) и
сохраняется в `settings.json` сам.

## Мотивация

Переключатель «статичная картинка / видеоролик» — лишний шаг: почти всегда
юзер знает, какой файл хочет в эфир, но не думает в терминах «тип источника».
Авто-подбор упрощает и сокращает flow «Открыть файл → готово», убирает
путаницу «выбрал mp4 в комбо статики — NO SIGNAL».

## Возможная реализация

- В UI один action «Выбрать медиа-файл…» (вместо «Открыть картинку…»/
  «Выбрать видео…»): OpenFileDialog с фильтром «Изображения и видео».
- Детект по расширению: `.png/.jpg/.jpeg/.bmp/.webp/.gif` → static,
  `.mp4/.mkv/.avi/.mov/.webm/...` → video. Неизвестное расширение —
  fallback-проба (декодером VideoFileSource / WIC) или warn-хинт.
- На Apply файл попадает в нужную секцию (`static.path` либо `video.path`),
  `source.type` выставляется соответствующе; `SettingsWatcher` делает
  hot-switch как сейчас.
- Камера остаётся отдельным выбором (файлов не касается).
- `VideoFileSource`/`StaticImageSource` без изменений — детект только на
  уровне UI/настроек.
- Опционально то же для дропа (см. `drag-drop-source.md`) и для CLI
  (`run --file` вместо `--type --path`).

## Связанное

- `drag-drop-source.md` — тот же UX-вайб, дроп файла вместо диалога.
- Секция video в `_videoInfoLabel` и хинты «статика vs видео» станут
  избыточными при выбранном файле — пересмотреть тексты.
